# API

FastAPI app: `src/pcb_ai/api/app.py`. Run with:

```powershell
.venv\Scripts\uvicorn pcb_ai.api.app:app --host 0.0.0.0 --port 8000
```

Analyses are held **in-memory** per process (`AnalysisService._store`);
there is no database-backed persistence in this version -- restarting the
API process loses prior `analysis_id`s. This is a documented limitation,
not an oversight (see DEVELOPMENT.md).

CORS is enabled for the origins listed in `CORS_ALLOW_ORIGINS` (defaults to
the Vite dev server, `http://localhost:5173`) so the [frontend](frontend)
can call this API directly in development.

Blocking pipeline/LLM calls (`analyze_pcb`, `analyze_demo_board`,
`query_pcb`) are offloaded to a worker thread via FastAPI's
`run_in_threadpool` rather than run inline in the `async def` handler --
otherwise a single multi-violation diagnosis request would block the
entire single-threaded event loop, stalling every other concurrent request
(including unrelated ones like `/health`). This was caught and fixed
during frontend integration testing: a background `/pcb/demo` request was
observed blocking a concurrent `/eval/summary` request until it finished.

## `GET /health`

```json
{"status": "ok", "kicad_available": false}
```

## `POST /pcb/analyze`

Multipart upload of a `.kicad_pcb` file. Runs the full pipeline
(parse -> **live** `kicad-cli` DRC -> context -> RAG -> LLM diagnosis ->
validation -> report) and returns:

```json
{"analysis_id": "...", "violation_count": 4, "kicad_executed": true, "kicad_available": true}
```

This endpoint always attempts **live** KiCad DRC (it does not accept a
fixture path, unlike the CLI's `--fixture-drc`, since a production API
should reflect the real installed DRC engine). If `kicad-cli` is
unavailable, `kicad_executed` is `false` and `violation_count` is `0`
(never fabricated) -- see `kicad_available` and the report's DRC-error
note for why.

## `POST /pcb/demo`

Runs (once, then caches under `analysis_id="demo"`) the full pipeline
against the bundled demo board + recorded DRC fixture
(`data/demo/sample_board.kicad_pcb` + `sample_drc_report.json`), so the
frontend has an instant, fully-diagnosed showcase view without requiring a
live KiCad install or re-running LLM diagnosis on every page load. Guarded
by an `asyncio.Lock` so concurrent calls (e.g. the frontend's mount-time
fetch racing a manual "reload demo" click) can't each trigger a redundant
run. Returns the same shape as `POST /pcb/analyze`. Kept as a dedicated
route (an alias for `POST /pcb/samples/small/analyze`) for backward
compatibility.

## `GET /pcb/samples`

Lists the bundled sample boards available for the frontend's sample-board
switcher: `small` (the original 4-violation demo board), `medium` (13
components / 8 violations spanning clearance, annular ring, courtyard
overlap, differential pair, zone clearance, a CRITICAL short circuit, and
minimum drill size -- generated by `scripts/generate_sample_boards.py`), and
`large` (26 components / 4 violations, sized for canvas zoom/pan and
violation-list-scrolling stress tests). Each entry reports whether it has
already been analyzed and cached in this server process (`cached: bool`).

## `POST /pcb/samples/{sample_id}/analyze`

Runs (once, then caches per `sample_id`) the full pipeline against the named
bundled sample board, mirroring `POST /pcb/demo`'s caching pattern but with
an independent lock per sample so concurrent requests for different samples
don't block each other. Returns the same shape as `POST /pcb/analyze`.

## `GET /pcb/analyze/{analysis_id}`

Board summary + counts for a prior analysis.

## `GET /pcb/board/{analysis_id}`

Full structured PCB JSON (`schema_version`, `board`, `layers`,
`components`, `pads`, `nets`, `tracks`, `vias`, `zones`, `rules`) for a
prior analysis -- everything the frontend's interactive board canvas needs
to render the physical layout at real (absolute, millimeter) coordinates.

## `GET /pcb/violations/{analysis_id}`

List of normalized `DRCViolation` objects (raw KiCad evidence preserved).

## `GET /pcb/violations/{analysis_id}/{violation_id}`

```json
{"violation": {...}, "diagnosis": {...}, "trace": {...}}
```

`diagnosis`/`trace` are `null` if that violation_id wasn't found (404) or
somehow has no diagnosis recorded.

## `GET /pcb/diagnoses/{analysis_id}`

Lightweight per-violation diagnosis summary (classification, confidence,
deterministic/LLM-assessed severity, human-review flag) for the frontend's
dashboard-level aggregate stats (average confidence, human-review count)
without fetching every violation's full evidence/trace payload:

```json
[{"violation_id": "drc-0", "classification": {"type": "clearance", "severity": "high", "confidence": 0.96}, "deterministic_severity": "high", "requires_human_review": false, "insufficient_evidence": false, "validation_passed": true}]
```

## `GET /pcb/report/{analysis_id}`

Plain-text Markdown engineering report (Phase 14).

## `POST /pcb/query`

```json
{"analysis_id": "...", "question": "Why is U3 pad 4 failing DRC?"}
```

Runs `InteractiveQueryAgent` (tool-calling loop) scoped to that analysis's
board/violations/knowledge base:

```json
{"answer": "...", "tool_calls": ["get_component", "get_net", "..."], "iterations": 3}
```

## `GET /eval/summary`

Reads the most recent `pcb-ai evaluate` run's aggregate metrics from
`results/ablation_results.json` (see EXPERIMENTS.md), for the frontend's
evaluation dashboard:

```json
{"available": true, "conditions": {"drc_only": {...}, "pcb_json_rag": {...}, "...": {}}}
```

Returns `{"available": false, "conditions": {}}` (not an error) if no
evaluation has been run yet in this environment.

## `GET /knowledge/showcase/summary`

Lists real component datasheets (curated from [pcb_qa-4FEE](pcb_qa-4FEE))
indexed into the standalone Knowledge Base showcase -- a hybrid-retrieval
RAG demonstration against genuine manufacturer PDFs, kept **isolated**
from the live diagnosis pipeline's own knowledge retriever (see
`pcb_ai.research.knowledge_showcase` module docstring for why: the real
datasheets belong to different hardware projects than the synthetic demo
board, and mixing them risks citing the wrong part's specs). Indexed
lazily on first request (~5s for 12 PDFs / ~300 chunks), cached thereafter:

```json
{"document_count": 12, "total_chunks": 294, "documents": [{"document_id": "acornrobotelectronics-u6", "document_name": "U6.pdf", "label": "U6 IC (AcornRobotElectronics)", "project": "AcornRobotElectronics", "chunk_count": 27, "page_count": 14}]}
```

## `POST /knowledge/showcase/search`

```json
{"query": "maximum reverse voltage rating", "top_k": 6}
```

Hybrid (metadata-filter + BM25 + TF-IDF) search over the real datasheet
showcase, returning ranked chunks with document/page provenance and
similarity scores:

```json
{"query": "...", "results": [{"document_name": "Meshinger/U6.pdf", "page": 3, "similarity": 0.6051, "text": "..."}]}
```

## `GET /research/pcb-qa-reference`

Read-only summary of the reference [pcb_qa-4FEE](pcb_qa-4FEE) benchmark
repository (component/net/subcircuit/question counts and sample QA pairs
per project), for the frontend's "Research Lineage" section:

```json
{"available": true, "projects": [{"project": "AcornRobotElectronics", "component_count": 262, "...": "..."}]}
```

This data is display-only -- pcb_qa-4FEE contains hierarchical
schematic/netlist circuit JSON with no physical layout/component-position
information, so it is never fed into the DRC diagnosis pipeline itself.

## Example (PowerShell + curl)

```powershell
$resp = curl.exe -s -X POST http://127.0.0.1:8000/pcb/analyze `
    -F "file=@board.kicad_pcb;type=application/octet-stream" | ConvertFrom-Json
curl.exe -s http://127.0.0.1:8000/pcb/report/$($resp.analysis_id)
```
